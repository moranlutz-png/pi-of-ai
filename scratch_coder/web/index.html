Scratch-Coder

Follow a piece of text left to right through the model — from raw characters, through embedding and each transformer block, to a guess at the next character. Each station shows what it does and the weights it's built from. It's small enough to see all the way through; it will never be a useful coder, and that's the point.

loading…

Each station's little squares are its weight tensors — the numbers that make up that step — sized by how many it holds. Brightness is how spread-out those numbers are; switch to Difference to see what training changed at each stage (at four layers, less than you'd guess, and not evenly). The route never changes: text in on the left, a next-character guess on the right.

Generate

Give it a few characters and it continues them — one character at a time, the whole forward pass running here in the browser with no server. It only ever saw Python source, so expect Python-flavoured shapes: indentation, def, brackets, names. At 0.84M parameters trained from scratch it will not write working code; seeing what structure it did pick up is the point.


    

  


  

    
Embedding neighbourhoods

    
Each character is a node placed where its learned embedding lands, projected to 3D, with lines to its nearest neighbours in the full 128-dimensional space — the connections the model has learned between characters. Drag to orbit, scroll to zoom, hover a character to read its neighbour list. A lightly-trained model may not have separated digits from letters from whitespace yet; tangled connections are the honest state of the model, not a bug.

    

      
      

    

    

      

      
    

    
Two lists sit side by side. Model now is the characters nearest the hovered one in the embedding the model has learned so far, by cosine similarity (−1 opposite … 1 identical). Ideal is what a fully trained model should recover — the characters the training text actually uses in the same contexts, measured straight from the corpus. A model-now character that also appears in the ideal list is one the model already gets right, so it turns green. Early on few match; that gap is how far it still has to go. (The two sets are scored differently, so the ideal numbers run higher — compare which characters appear, not the exact values.) Whitespace has no glyph, so: ␠ space · ↵ newline · ⇥ tab · ␍ carriage return.

  


  

    
Live attention

    
Attention is how the model decides which earlier characters matter while it processes each one. Type a prompt and every head computes it here in the browser — no sampling, just the real forward pass.

    

      
      
    

    

    

      How to read one square (heatmap):
      
    
        
  • Each little grid is one head. There are several heads per layer (a row of grids), and several layers stacked down the page — each one a separate "reader" that can look at the text differently.
    • 
        
  • The characters run along the top and the left of every grid. To read a square: go to a row (the character being processed) and slide across to a column (a character it looked back at).
    • 
        
  • Brighter = more attention. A bright square at row “(”, column “o” means: while processing the (, this head leaned on the earlier o. Hover any square to read it as a sentence.
    • 
        
  • It's a triangle, not a full square, because a character can only see itself and what came before it — never the future.
    • 
        
  • Common shapes: a bright diagonal = "attend to myself"; a bright stripe just below it = "attend to the previous character"; a bright first column = "attend back to the very start".
